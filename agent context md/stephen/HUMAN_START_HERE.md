## Your question and purpose

You own whether the separate engineering pieces support a distinctive scientific result. Establish shared contracts, then design a profiling-budgeted intervention method and fair comparisons. The target result is decision quality and net benefit on new verifiable goals, accounting for profiling cost, correctness and latency. A successful implementation does not establish that the method is novel or competitive.

## Work you own as a human

Confirm collaborator GitHub accounts, individual cluster access and bounded sessions. Agree interfaces and concrete examples with the team, review PRs, and resolve overlapping changes. Own the research question, task realism, baseline fairness, uncertainty and go/no-go decision after pilot evidence. Keep the held-out boundary intact and review relevant literature before asserting novelty.

## Work your agent should execute

Have your agent inspect the current baseline, propose exact callable/record types and small compatible examples, review component contracts, and prepare integration checks. It can implement analysis and baseline comparisons and check evidence consistency. It should distinguish hypothetical benefits from measured results and prepare reviewable changes; it does not self-merge or silently change a frozen experiment.

Begin locally on contracts and method design. ## What done means

The first deliverable is a reviewed common interface agreement with example artifacts, a recorded runtime decision path and clear owners. Next integrate one verified measured goal, inspect pilot evidence and compare the method against simple screening and profiling alternatives. Proceed to frozen held-out evaluation only if the evidence supports the proposed contribution; document a direction change if it does not.

## Start and finish each session

Read your issue and the current shared context; state any unresolved contract assumption. Your agent works on a named issue branch from current integration, opens a draft PR early, tests on that branch and pushes scoped changes autonomously. Stephen reviews and decides merges. Review a representative output yourself and report a specific blocker rather than waiting silently. When another PR is pending, continue independent work in a separate issue branch.

At the end, provide the PR link, tested commit, exact test results, example artifact, remaining evidence and next action. Have the agent publish its reviewable context summary with author `stephen` after every completed turn using the [shared protocol](../README.md). Context publication is separate from code review; it does not merge implementation changes. See [dependencies and hardware](../DEPENDENCIES_AND_HARDWARE.md) for the later gates.
